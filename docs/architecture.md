## Что реализовано

Этот документ описывает ML-часть и приложение, исходники которых находятся в [`ml/`](../ml/) и [`backend/`](../backend/) этого репозитория. Выбранная модель — **route-specific regime-aware robust seasonal ensemble**: ансамбль устойчивых сезонных профилей с отдельными настройками по маршрутам. Её вход — исторические почасовые агрегаты и заданная сетка будущих часов. Выход — файл `route;date;hour;prediction`, который можно проверить и передать в систему оценки. Обучение и прогноз выполняются командами из [ML-инструкции](../ml/README_ML.md). Прогноз рассчитывается пакетно: HTTP-сервис читает готовый CSV, а не запускает модель при запросе.

| Компонент | Назначение | Результат |
|---|---|---|
| [`ml/src/load_data.py`](../ml/src/load_data.py) | Читает CSV с разделителем `;`, ограничивает историю 31 октября 2025 года и восстанавливает отсутствующие часы нулями. | Полная историческая сетка 10 маршрутов × 304 дня × 24 часа; сетка прогноза на 61 день. |
| [`ml/src/features.py`](../ml/src/features.py) | Добавляет календарный режим и рассчитывает робастные профили `маршрут × день недели × час`. Смешивает стабильную и консервативную конфигурации по маршрутам; для 7 и 25 корректирует почасовые доли. | Базовый прогноз без будущих сетевых событий. |
| [`ml/src/validate.py`](../ml/src/validate.py), [`ml/src/metrics.py`](../ml/src/metrics.py) | Проверяют модель с фиксированной датой отсечения: май–июнь, июль–август, сентябрь–октябрь; октябрь — отдельная диагностика. Метрика — `1 − WAPE`. | Оценки временных проверок. |
| [`ml/src/train.py`](../ml/src/train.py) | Запускает проверки и записывает выбранную конфигурацию и результаты. | [`seasonal_route_model.json`](../ml/models/seasonal_route_model.json), `ml/predictions/validation_scores.csv`. |
| [`ml/src/predict.py`](../ml/src/predict.py), [`ml/src/interventions.py`](../ml/src/interventions.py) | Считают базовый прогноз, затем применяют сценарии календаря и сети: рабочая суббота, новый маршрут 5, T1, изменения маршрутов 7 и 50. Ограничивают значения снизу нулём и округляют. | [`ml/outputs/submission.csv`](../ml/outputs/submission.csv), 14 640 строк. |
| [`ml/scripts/check_submission.py`](../ml/scripts/check_submission.py) | Проверяет формат и ключи сохранённого прогноза. | Проверенный файл для отправки. |

Первичная обработка и аудит данных воспроизводятся скриптом [`data_preparation/prepare.py`](../data_preparation/prepare.py); описание политик пропусков и выходных файлов — в [README обработки](../data_preparation/README.md). Оптимизация сериализации из нагрузочной копии перенесена в основной backend.

## Поток данных и воспроизводимость

1. Данные соревнования размещаются локально по структуре из [`ml/data/README.md`](../ml/data/README.md). Большой исходный архив в Git не хранится.
2. История до даты начала каждого проверочного периода используется для построения профилей. Факты проверочного периода нужны только для метрики; при финальном прогнозе после 31 октября они недоступны.
3. `train.py` записывает JSON с параметрами и оценками. При инференсе `predict.py` **не загружает** этот JSON: он использует те же конфигурации, заданные в `features.py`. Поэтому для воспроизведения нужны код и исторические CSV, а JSON служит паспортом выбранной версии.
4. `predict.py` применяет события **один раз**. Готовый `submission.csv` уже содержит эти поправки; повторять их при показе прогноза нельзя. Даты и происхождение внешних сведений описаны в [реестре источников](external_sources_for_final_solution/README.md).

## Приложение и контракт между частями

Исходники FastAPI-сервиса, данные для него и браузерный дашборд находятся в [`backend/`](../backend/). Приложение читает результат пакетного ML-расчёта; отдельного онлайн-инференса и отдельного frontend-сервера нет. Историческая копия сервиса для нагрузочных измерений сохранена в [`docs/performance/`](performance/README.md).

| Слой | Код и данные в репозитории | Роль |
|---|---|---|
| Точка входа | [`backend/app/main.py`](../backend/app/main.py) | Создаёт FastAPI-приложение, подключает роутеры и статический дашборд; при старте загружает прогноз, географию и события. |
| Прогноз | [`data_loader.py`](../backend/app/data_loader.py), [`routers/forecast.py`](../backend/app/routers/forecast.py), [`submission.csv`](../backend/data/submission.csv) | Хранит прогноз в pandas, фильтрует по маршруту, диапазону дат и часу, отдаёт точки и сводки маршрутов. |
| География | [`geo_loader.py`](../backend/app/geo_loader.py), [`routers/geo.py`](../backend/app/routers/geo.py), [`route_stops_map.csv`](../backend/data/route_stops_map.csv) | Возвращает остановки по `trip_id`, `direction_id` и `stop_sequence` после проверки пригодности координат. |
| События | [`events_loader.py`](../backend/app/events_loader.py), [`routers/events.py`](../backend/app/routers/events.py), [`calendar_and_events.json`](../backend/data/calendar_and_events.json) | Объясняет уже учтённые моделью календарные и сетевые события; **не меняет** `prediction`. |
| Выгрузка | [`routers/export.py`](../backend/app/routers/export.py) | Формирует отфильтрованные CSV и XLSX без временных файлов. |
| Интерфейс | [`backend/app/static/index.html`](../backend/app/static/index.html) | Показывает график, таблицу и карту. Сценарий «что если» рассчитывается в браузере отдельно от базового прогноза. |

Контракт между ML и API — CSV с одной строкой на `route × date × hour` и полями `route;date;hour;prediction`. Файлы [`ml/outputs/submission.csv`](../ml/outputs/submission.csv) и [`backend/data/submission.csv`](../backend/data/submission.csv) побайтно совпадают (SHA-256 `364b9a9d2db0230b8ba430407d84299c5a21f819eb09ce1088b2c75b19051d1d`); оба содержат 14 640 прогнозов. Применённые при расчёте события не следует накладывать в API повторно.

Браузер получает список маршрутов через `/forecast/routes`, выбранный срез через `/forecast`, пояснения через `/events/applied`, остановки через `/geo/route/{route}` и выгрузки через `/export/csv` и `/export/xlsx`. Представления «день», «месяц» и «весь период» используют один API с разными границами дат. География доступна только для маршрутов **1, 5, 7, 11, 12**. Линии между остановками схематичны; почасовой прогноз относится ко **всему маршруту**, а не к каждой остановке.

## Работа сервиса и проверка

В приложении предусмотрены дашборд `/`, проверка состояния `/health` и OpenAPI `/docs`. Прогноз, география и реестр событий загружаются в память при старте; после замены CSV сервис нужно перезапустить. Для демо CORS разрешает все источники.

[Отдельная копия для тестирования](performance/README.md) прошла локальный HTTP-нагрузочный тест: 9 650 запросов без ошибок; смешанный сценарий — 646 RPS и p95 97 мс на машине из [отчёта](performance/docs/performance_and_features.md). Эти показатели относятся именно к протестированной копии; для основной сборки тест нужно повторить в целевой среде.
