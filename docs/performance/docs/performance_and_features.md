# Производительность и дополнительные возможности

## Краткий итог

28 сентября 2026 года выполнен локальный HTTP-нагрузочный тест backend с одним Uvicorn worker. Всего отправлено **9 650 запросов, ошибок — 0**. В смешанном рабочем сценарии сервис обработал **646 RPS**, `p95 = 97 мс`. Даже полная выдача всех 14 640 прогнозных точек после оптимизации имеет `p95 = 93 мс`.

## Среда тестирования

- MacBook Air, Apple M2, 8 ядер, 8 GB RAM;
- macOS 26.6 arm64;
- Python 3.13.5;
- FastAPI 0.141.1, Uvicorn 0.54.0;
- один worker, access log выключен;
- локальный HTTP по `127.0.0.1`, без TLS, reverse proxy и внешней сети;
- 14 640 строк прогноза загружаются в память один раз при старте.

Сырые результаты находятся в `docs/performance/*.json`, объединённая сводка — в `docs/performance/results_summary.json`.

## Выполненная оптимизация

Первый замер полной выдачи выявил медленную построчную сборку 14 640 Pydantic-объектов: `p95 = 1 990.9 мс`. Эндпоинт переведён на векторизованную JSON-сериализацию уже проверенного при старте DataFrame. После изменения `p95 = 93.1 мс`, ускорение — **в 21.4 раза**, формат ответа не изменился.

## Как повторить тест

Запуск сервиса:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-loadtest.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

В другом терминале:

```bash
python tests/smoke_test.py --base-url http://127.0.0.1:8000
python tests/load_test.py --scenario health --requests 5000 --concurrency 100
python tests/load_test.py --scenario typical --requests 4000 --concurrency 50
python tests/load_test.py --scenario full_forecast --requests 100 --concurrency 5
python tests/load_test.py --scenario csv_export --requests 500 --concurrency 20
python tests/load_test.py --scenario xlsx_export --requests 50 --concurrency 3
```

Для замера памяти и CPU передайте PID сервера через `--server-pid PID`. Без этого параметра latency, RPS и ошибки измеряются как обычно.

## Реализованные дополнительные возможности

1. Единый web-дашборд и REST API в одном сервисе.
2. Фильтрация прогноза по маршруту, дате, диапазону дат и часу.
3. Три представления горизонта: день, месяц и весь доступный период.
4. Интерактивный график, таблица, суммарные показатели и почасовая детализация.
5. Сценарий «что если»: мероприятие `+10%/+35%` и ограничение движения `−15%`; сценарные цифры визуально отделены от базового прогноза.
6. Пояснение календарных и транспортных событий, уже учтённых ML-моделью, со ссылками на источники.
7. Карта остановок и обоих направлений маршрута для маршрутов 1, 5, 7, 11 и 12; цветовая индикация относительной загрузки.
8. Экспорт отфильтрованных данных в CSV и XLSX без создания временных файлов.
9. Swagger/OpenAPI на `/docs`, health-check `/health`, CORS для подключения отдельного frontend.
10. Проверка схемы входного CSV и типов при старте, понятные ошибки API и `404` для маршрутов без географии.
11. Загрузка прогноза, геоданных и событий один раз в RAM — база данных не нужна для объёма 14 640 строк.
12. Публикация методологии внешних источников через сервис и хранение итогового v3 submission внутри репозитория.

## Ограничения замера

Результаты характеризуют конкретную локальную машину и loopback-сеть. В production итоговая latency также зависит от контейнера, reverse proxy, TLS и сети клиента. Для горизонтального масштабирования Uvicorn можно запускать с несколькими workers; текущие цифры намеренно получены на одном worker.
